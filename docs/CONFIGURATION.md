# Configuration reference

`KeyPassXCCloudSync.ini` is generated by the application and may be explicitly selected with `--config`. Editing it manually is intended for diagnosis and advanced deployment, not ordinary onboarding. Configuration contains **no plaintext vault password, cloud secret key or refresh token**; Windows Credential Manager contains those secrets. Keep config and state separate on every computer.

## Configuration file structure

`[General]`:

| Key | Meaning | Default |
| --- | --- | --- |
| `LocalFile` | Absolute or config-relative path to an existing `.kdbx` file | Required |
| `StateFile` | Path to local state JSON; its parent is the data directory | `data/state.json` |
| `TrayEnabled` | Enable tray behavior | `true` |
| `SyncEnabled` | Local permission to publish vault changes (initially paused) | `false` |

`[Sync]`:

| Key | Meaning | Allowed / default |
| --- | --- | --- |
| `PollSeconds` | Default remote polling interval | 10–86400 / 60 |
| `StatsPublishMinutes` | Publication cadence of aggregated statistics | 1–10080 / 60 |
| `DebounceMs` | Local-change settle delay | 0–600000 / 1500 |
| `StableFileCheckMs` | File stability observation | 100–60000 / 1200 |
| `RetrySeconds` | Retry delay following a failure | 1–3600 / 60 |

`[Notifications]`: `OfflineAfterMinutes` — 1–10080, default 30.

`[Backup]`: `MinCopies` — 20–10000, default 20; `MinDays` — 30–3650, default 30; `OnStartup` — `false` unless enabled; `KeepStartupCopies` — 1–999, default 30.

`[Logging]`: `Level` — `Info` or `Debug`, default `Info`; `MaxSizeMB` — 1–100, default 5; `MaxFiles` — 1–100, default 5.

`[UI]`: `Theme` (internal localized theme values; select Automatic, Dark or Light from the UI), `Language` (`auto`, `en`, `ru`, `uk`), `RememberWindowPosition` (`true` or `false`). These are UI data values and **not the language of project documentation**.

## Cloud sections

Use one `[Cloud.NAME]` section for each cloud, with a unique safe name. Common keys: `Enabled=true`, `Provider`, `RemoteDirectory`, `CloudId`, `PollSeconds` and `TimeoutSeconds` (5–3600 seconds, default 120). The remote directory is a safe relative slash-delimited path; it may not contain empty segments, `..`, backslashes or colon. Cloud IDs are independent of display names.

| Provider | Additional keys | Authentication |
| --- | --- | --- |
| `GoogleDrive` | `ClientId`, optional `ClientSecretCredential`, `RefreshCredential`, `AccountLabel`, `GoogleFolderCacheSeconds` (0–60, default 10) | OAuth, local Credential Manager targets |
| `ProtonDrive` | Optional `Executable` | Official CLI authenticated session; fixed internal root `/my-files` |
| `S3` or `CloudflareR2` | `BaseUrl` (HTTPS endpoint), `RootPath` (bucket), `S3Region`, `CredentialTarget` | Access key ID and secret held in Credential Manager |
| `WebDAV` | `BaseUrl` (HTTPS WebDAV endpoint), `CredentialTarget` | Credentials held in Credential Manager |

The official build includes a built-in Google **Desktop app** OAuth client in `GoogleOAuthClientDefaults.cs`. For a new Google connection, `ClientId` and `ClientSecretCredential` may be omitted; the refresh token remains in Windows Credential Manager. An explicit `ClientId` or `ClientSecretCredential` takes precedence and may require reauthorization. The embedded Desktop client identity is publicly extractable and must not be confused with a refresh token or a service-account credential. Confirm that the Google OAuth client was created with application type **Desktop app**.

`RootPath` is **not** a Proton setting. It remains an S3 bucket setting. The Proton CLI cache is not configured by the application. Unknown provider-specific INI keys are **rejected**, not ignored, so unsupported path and authentication settings cannot silently redirect a connection. This is a clean first release and includes no automatic configuration upgrade procedure. With no `Executable`, the Windows adapter first checks beside the running application (including its portable `tools/` directory and, when distinct, the INI directory), then searches absolute directories listed in the Windows `PATH` environment variable. A manually selected path always takes precedence. Use the Browse button to choose a file and Auto to clear an override. Proton account identity is owned by the CLI; the former `AccountLabel` is ignored if present in an existing local INI and is never written by the current editor.

## Sample

```ini
[General]
LocalFile = C:\Vaults\Passwords.kdbx
StateFile = C:\Vaults\CloudSyncData\state.json
TrayEnabled = true
SyncEnabled = false

[Sync]
PollSeconds = 60
StatsPublishMinutes = 60
DebounceMs = 1500
StableFileCheckMs = 1200
RetrySeconds = 60

[Notifications]
OfflineAfterMinutes = 30

[Backup]
MinCopies = 20
MinDays = 30
OnStartup = false
KeepStartupCopies = 30

[Logging]
Level = Info
MaxSizeMB = 5
MaxFiles = 5

[UI]
Language = en
RememberWindowPosition = false

[Cloud.PersonalProton]
Enabled = true
Provider = ProtonDrive
RemoteDirectory = Passwords/KeePassSync
PollSeconds = 180
TimeoutSeconds = 120
```

The sample is illustrative. Do not publish real account identifiers, credentials or personal filesystem locations. The actual Proton account session is maintained by the CLI; the application does not ask for an unverified account label.

## Configuration and identity safety

Do not set two independent vaults to one `RemoteDirectory`. Do not duplicate `CloudId`; connection names may change without rotating the identity, but changing the actual bucket, endpoint, or remote directory constitutes a different storage location and must be handled as a new connection. `state.json` and private credentials must not be copied to another computer. Do not enable synchronization merely because a cloud responds to a connectivity probe; run the full isolated test and conflict preflight.
